01
Концепция
Что такое BIM-канал и механика spec-in
BIM-канал — цифровая библиотека, где производитель публикует «BIM-объекты» своих коллекций (файлы для Revit, Renga, nanoCAD). Архитектор скачивает и вставляет плитку в модель здания. Продукт, зафиксированный в спецификации до тендера, почти не меняется при закупке — это механика spec-in.

Обычные продажи сегодня

  • Узнаём о проекте на стадии тендера
  • Конкурируем с 5–15 аналогами по цене
  • Win rate: 15–25%
  • Маржа давится ценовой войной

Spec-in через BIM-канал

  • Архитектор сам выбирает LAPARET в BIM
  • Продукт в спецификации до тендера
  • Win rate: 70–85%
  • Заменить сложно — маржа сохранена

Механика — верифицировано
Как работает BCI Central / Hubexo (NBS Source) изнутри
BCI Central основана в Австралии в 1998 г., куплена шведской Byggfakta Group в 2021 г., с 01.10.2024 весь холдинг = Hubexo. Для производителей материалов ключевой продукт — Product Information + Specification (в APAC = Archify, в UK/US/CA/AU = NBS Source + NBS Chorus).
📋
1. Онбординг
Продавец обращается к NBS-команде. Не self-serve — обязателен sales-звонок.
📦
2. Контент
Загрузка продуктов: карточки, сертификаты, BIM-объекты Revit. NBS может сделать сам (Premium).
🔍
3. Поиск
Архитектор ищет в NBS Source по категории, стандарту, характеристике.
✏️
4. Спецификация
Нажимает «Specify» — продукт в NBS Chorus-проект. Привязка к комнате.
📊
5. Лид
Вы видите: бюро, проект, контакт. Звонок до тендера. Win rate 70–85%.

Ключевое отличие Hubexo от BIMLIB
BIMLIB = пассивная библиотека (скачали — неизвестно кто). Hubexo = активная воронка продаж: вы видите конкретное бюро, конкретный проект, имя архитектора — и выходите на него до тендера. Это не библиотека — это CRM по архитекторам с аналитикой в реальном времени.

Технология · AI + MCP · Верифицировано
Как AI-агенты и MCP-протокол помогают загружать каталог
MCP (Model Context Protocol, Anthropic) позволяет AI-агенту вызывать внешние API как инструменты. Если у платформы есть REST API — агент может создавать продукты, загружать свойства, управлять контентом. BIMobject — единственная платформа с публичным документированным REST API.

BIMobject Publish API — что реально можно сделать агентом

# Три эндпоинта BIMobject Publish API (github.com/bimobject/api-documentation): # Аутентификация: OAuth 2.0 client_credentials # Swagger: https://publish-publicapi.bimobject.com/swagger/index.html POST /v2/brands/{brandId}/products # Создать продукт PUT /v2/brands/{brandId}/products/{id} # Обновить продукт PUT /v2/brands/{brandId}/products/{id}/propertyvalues # Задать характеристики POST /v2/brands/{brandId}/products/{id}/files # Загрузить файл (фото, документ) # Типы свойств: Text, Boolean, Int, Decimal, Date — поддержка диапазонов
Как мог бы работать MCP-агент для BIMobject
Шаг 1: Агент получает Excel-каталог LAPARET (название, размеры, характеристики).
Шаг 2: LLM извлекает и структурирует поля — name, category, R-value, dimensions, finish type.
Шаг 3: Агент вызывает BIMobject Publish API → создаёт продукты в аккаунте бренда.
Шаг 4: Загружает фото и технические PDF через Files-эндпоинт.
Узкое место: загрузка .rfa-файла (BIM-объект Revit) через API — не подтверждена публичными доками; требует прямого запроса в BIMobject. Создание .rfa автоматически не возможно без Dynamo-скрипта.

Что строим: MCP-агент для BIMobject
BIMobject — единственная платформа, где автоматизация через AI-агент реальна. Нужно построить MCP-сервер, который оборачивает BIMobject Publish API: принять каталог Excel → создать продукты → загрузить свойства → приложить файлы. Это устранит ручной труд при загрузке 200+ коллекций. Оценка разработки MCP-коннектора: 2–4 нед. одного backend-разработчика. Аутентификация через OAuth2 client_credentials — стандартная, документирована.

Создание BIM-объекта (.rfa): сроки и стоимость

Простое параметрическое семейство плитки

  • Плоская геометрия (прямоугольник)
  • Параметры: ширина, высота, толщина
  • Создание вручную: 3–6 ч опытного BIM-моделлера
  • Одна .rfa покрывает всю серию с разными форматами

Dynamo batch-скрипт (полуавтоматизация)

  • Пишется один раз для типа «плоская плитка»
  • На вход — Excel с размерами 200 серий
  • Генерирует 200 .rfa-файлов пакетом
  • Разработка скрипта: 1–2 нед. разработчика Dynamo
  • После: QA на выборке (~20 семейств)

Аутсорс моделлеру (без скрипта)

  • Рыночная ставка: $30–80/семейство
  • 200 серий × $50 ≈ $10 000
  • Срок: 6–10 нед. (параллельно)
  • Через BIMLIB Omega — персонал BIMLIB делает модели

Оценка стоимости аутсорса .rfa — ориентировочная, не верифицирована из публичного источника. Dynamo batch-скрипт для простой геометрии плитки — реальное решение, используемое в индустрии (RevitBatchProcessor, github.com).

Стратегия: начать с топ-20, не со всеми 200
Запускать весь каталог сразу = месяцы подготовки. Правильная тактика: топ-20 коллекций по продажам → BIMLIB БЕТА (160K ₽) → измерить скачивания → расширять то, что качают. Параллельно — Dynamo-скрипт для batch-генерации остальных 180 серий. .rfa-файлы от BIMLIB Omega или аутсорс. BIMobject (глобал) — после получения .rfa и регистрации developer-ключа.

Следующие шаги — приоритизированный список

Октябрь 2026 — что делаем прямо сейчас

  • 1. Заключить договор с BIMLIB БЕТА (160 000 ₽). Отобрать топ-20 коллекций. Назначить ответственного менеджера. Срок: неделя 1–7 окт.
  • 2. Запустить производство .rfa-семейств — либо через Omega-тариф BIMLIB (включено), либо нанять BIM-моделлера. Параллельно: собрать техдокументацию от поставщика.
  • 3. Запрос в NBS Source (Фаза 2): отправить письмо на salessupport@theNBS.com — узнать цены и требования для иностранного поставщика через ОАЭ.
  • 4. Запрос в Renga BIM-каталоги: bimcatalogs.rengabim.com — уточнить условия входа (КНАУФ там уже есть).
  • 5. Первый контакт с Nitco / Simpolo (Морби): письмо об интересе к эксклюзивному spec-in агентству для UK/AU рынков.
  • 6. Оценить юрлицо ОАЭ: запросить у Ajman Free Zone / Virtuzone — стоимость и срок регистрации.
